## 1. Scope

TriCore V3 is a sequence operator with three independently ablatable mechanisms:

1. **Engine I — Surprise-Gated State Collapse:** a gated recurrent vector state `h_t`.
2. **Engine II — Causal Shifted Multi-Head Fast Weights:** a delta-rule associative matrix `F_t` that binds `K_{t-1}` to `V_t`.
3. **Engine III — Surprise-Scaled Equilibrium Refinement:** a fixed-step MLP refinement loop whose step size is scaled by surprise.

The specification has three non-goals:

- It does **not** claim natural-language or reasoning capability.
- It does **not** claim superiority over a tuned Transformer.
- It does **not** claim that Engine III is necessary for MQAR.

The evidence is a single-seed, 600-step MQAR experiment. The result is an existence demonstration: a causal shifted fast-weight memory can solve this task with an O(1) state.

## 3. Model contract

### 3.1 `TriCoreBlock`

Constructor:

```python
TriCoreBlock(
    d_model: int = 128,
    n_heads: int = 4,
    d_head: int = 32,
    max_loops: int = 2,
)
```

Forward:

```python
forward(x, enable_fast_weight=True, enable_adaptive_loop=True) -> (y, surprise_trace)
```

Input/output:

- `x: [B, L, D]`
- `y: [B, L, D]`
- `surprise_trace: [B, L]`

Parameter inventory per block:

| Component | Module | Shape / count |
| :--- | :--- | :--- |
| Input norm | `in_norm` | `LayerNorm(D)` |
| Causal conv | `short_conv` | depthwise `Conv1d(D, D, k=3, padding=2, groups=D)` |
| State projection | `u_proj` | `Linear(D, D)` |
| Surprise gate | `surprise_gate` | `Linear(D, D)` |
| Base decay | `base_decay_logit` | `[D]`, initialized `linspace(1.0, 3.0, D)` |
| Q/K/V | `proj_q`, `proj_k`, `proj_v` | each `Linear(D, H*d_head, bias=False)` |
| Readout | `proj_out` | `Linear(H*d_head, D, bias=False)` |
| Fast LR | `fast_lr_logit` | `[1, H, 1, 1]`, initialized `0.5` |
| Fast decay | `fast_decay_logit` | `[1, H, 1, 1]`, initialized `3.5` |
| Think norm | `think_norm` | `LayerNorm(D)` |
| Think MLP | `think_mlp` | `D -> 2D -> D`, GELU |
| Output norm | `out_norm` | `LayerNorm(D)` |

### 3.2 Causal input path

```math
u_t = \operatorname{LN}(x_t)
```

```math
c_t = \operatorname{SiLU}\!\left(b + \sum_{j=0}^{2} w_j \odot u_{t-j}\right),
\qquad
\tilde{u}_t = W_u c_t + b_u
```

The convolution is depthwise, kernel 3, left padding 2, and the output is truncated to the first `L` positions. `c_t` uses only `u_{t-2}, u_{t-1}, u_t`.

Parallel projections before the recurrence:

```math
Q_t = \operatorname{normalize}(W_q u_t), \quad
K_t = \operatorname{normalize}(W_k u_t), \quad
V_t = W_v c_t
```

with shapes `[B, L, H, d_head]`; normalization is L2 over the head dimension.

### 3.3 Engine I

```math
e_t = |\tilde{u}_t - h_{t-1}|
```

```math
g_t = \sigma(W_s e_t + b_s)
```

```math
h_t = \lambda \odot (1 - 0.5 g_t) \odot h_{t-1} + g_t \odot \tilde{u}_t,
\qquad
\lambda = \sigma(\lambda_{\text{logit}})
```

```math
s_t = \frac{1}{D}\sum_{j=1}^{D} g_{t,j}
```

State: `h_t: [B, D]`. The code uses `h = base_decay * (1.0 - 0.5 * g_t) * h + g_t * u_t` with `h` initialized to zeros.

### 3.4 Engine II

Initial state: `F_0 = 0`, shape `[B, H, d_head, d_head]`; `prev_k = 0`, shape `[B, H, d_head, 1]`.

For `t > 0`:

```math
F_t =
\lambda_f \odot F_{t-1}
+ \eta_{\text{eff},t} \odot
(V_t - F_{t-1} K_{t-1}) K_{t-1}^{\top}
```

```math
\eta_{\text{eff},t} = \eta \odot (0.3 + 0.7 s_t),
\qquad
\eta = 0.9\,\sigma(\eta_{\text{logit}}),
\qquad
\lambda_f = \sigma(\lambda_{f,\text{logit}})
```

Read after the write:

```math
r_t = F_t Q_t,
\qquad
z_t = h_t + W_o \operatorname{vec}(r_t)
```

At `t = 0`, no write occurs; `r_0 = F_0 Q_0 = 0`. The implementation stores `prev_k = K_t` at the end of each step for the next shifted write.

State: `F_t` is `H * d_head * d_head` floats per layer; `prev_k` is `H * d_head` floats per layer. Neither depends on `L`.

### 3.5 Engine III

Fixed `L_max` loop, vectorized across `L`:

```math
z^{(0)} = z
```

```math
z^{(i+1)} = z^{(i)} + \frac{s_t}{i+1}\operatorname{MLP}(\operatorname{LN}(z^{(i)})),
\qquad i = 0,\ldots,L_{\max}-1
```

Output:

```math
y = x + \operatorname{LN}(z^{(L_{\max})})
```

Engine III has no independent state. Surprise scales the step size; it does **not** choose the number of steps.

### 3.6 Ablation semantics

| Flag | Effect |
| :--- | :--- |
| `enable_fast_weight=False` | Engine II is skipped; `z = h_seq`; no fast-weight reads or writes |
| `enable_adaptive_loop=False` | Engine III is skipped; output uses `z` directly |
| Both `True` | Full 3-in-1 block |

The flags gate compute only. Modules are constructed regardless of the flags, so all TriCore variants report the same parameter count.

### 3.7 `TriCoreLM`

```python
TriCoreLM(
    vocab_size: int,
    d_model: int = 128,
    n_layers: int = 2,
    d_fast: int = 32,
    max_loops: int = 2,
    enable_fast_weight: bool = True,
    enable_adaptive_loop: bool = True,
)
```

`d_fast` is passed to `TriCoreBlock` as `d_head`; `n_heads` is fixed at 4 in the LM wrapper. The embedding has no positional table. `final_norm` and a bias-free `lm_head` produce logits. The returned surprise is the mean across layers.

### 3.8 `BaselineTransformerLM`

```python
BaselineTransformerLM(
    vocab_size: int,
    d_model: int = 128,
    n_layers: int = 2,
    n_heads: int = 4,
    max_seq_len: int = 2048,
)
```

Learned absolute positional embeddings, pre-norm `TransformerEncoderLayer`, GELU, FFN width `2*d_model`, dropout 0, causal mask via `generate_square_subsequent_mask(L)`, and `is_causal=True`.

## 4. State, parameter, and cache accounting

### 4.1 Persistent state

For `D = 128`, `H = 4`, `d_head = 32`, `n_layers = 2`:

| State | Shape per layer | Floats per layer | Bytes per layer (FP32) |
| :--- | :---: | :---: | :---: |
| `h` | `[B, 128]` | 128 | 512 |
| `F` | `[B, 4, 32, 32]` | 4,096 | 16,384 |
| `prev_k` | `[B, 4, 32, 1]` | 128 | 512 |
| **Strict total** | | **4,352** | **17,408** |

Two layers: **34,816 bytes ≈ 34.0 KiB**.

This is an inference-state claim. Training still stores per-token activations and sequence-length lists for backpropagation, so training memory is not O(1) in `L`.

The benchmark report uses the specified accounting formula that counts `h` and `F` but not `prev_k`:

```math
C_{\text{report}} =
\frac{n_{\text{layers}} (D + H d_{\text{head}}^2) \times 4}{1024}
=
\frac{2(128 + 4 \cdot 32^2) \times 4}{1024}
= 33.0\text{ KiB}.
```

This is the number used in `results/BENCHMARK_REPORT.md` and the plot. The strict persistent state is about 1 KiB larger. Both are constant in `L`.

### 4.2 Transformer KV cache

```math
C_{\text{KV}}(L) =
\frac{n_{\text{layers}} \cdot 2 \cdot L \cdot D \cdot 4}{1024}\text{ KiB}
=
\frac{2 \cdot 2 \cdot L \cdot 128 \cdot 4}{1024}\text{ KiB}.
```

At `L = 32,768`, this is `65,536 KiB`. The report's reduction factor is `65,536 / 33 = 1,985.9×`.

### 4.3 Parameter count

The benchmark reports **348,432** trainable parameters for every TriCore variant and **543,744** for the Transformer. The Transformer count includes a `2048 × 128 = 262,144` positional embedding; without it, the baseline has 281,600 parameters. TriCore has no positional embedding table. These are not matched-parameter comparisons.

All TriCore ablation variants register the same modules, so disabling an engine does not change the parameter count.

## 6. Latest benchmark record

**Generated by:** `python run_experiment.py`  
**Report:** `results/BENCHMARK_REPORT.md`  
**Plot:** `results/tricore_vs_transformer.png`  
**Run configuration:** seed 42, 600 steps, batch 64, AdamW `lr=3e-3`

### 6.1 Accuracy and ablation

| Architecture variant | Parameters | Final val loss | In-domain recall | 4× noise-gap extrapolation | Train time |
| :--- | :---: | :---: | :---: | :---: | :---: |
| **TriCore Full (3-in-1)** | 348,432 | **0.0012** | **100.00%** | **99.45%** | 129.5 s |
| TriCore No Fast-Weight | 348,432 | 3.4330 | 3.28% | 3.83% | 60.6 s |
| TriCore No Adaptive Loop | 348,432 | **0.0012** | **100.00%** | **99.84%** | 126.0 s |
| Vanilla Transformer | 543,744 | 2.8272 | 13.12% | 13.05% | 16.4 s |

### 6.2 Cache scaling

| Sequence length | Transformer KV cache | TriCore O(1) state | Reduction |
| :---: | :---: | :---: | :---: |
| 128 | 256.00 KB | 33.00 KB | 7.8× |
| 512 | 1,024.00 KB | 33.00 KB | 31.0× |
| 2,048 | 4,096.00 KB | 33.00 KB | 124.1× |
| 8,192 | 16,384.00 KB | 33.00 KB | 496.5× |
| 32,768 | 65,536.00 KB | 33.00 KB | 1,985.9× |

The 33.00 KB column is the report formula `n_layers * (d_model + 4*d_fast*d_fast) * 4 / 1024`. The strict implementation state, including `prev_k`, is about 34.0 KiB.

### 6.3 Interpretation

1. **Engine II is necessary for this task.** Full vs No Fast-Weight: 100.00% → 3.28% in-domain and 99.45% → 3.83% extrapolation. Validation loss rises from 0.0012 to 3.4330. Causal shifted binding is the mechanism that solves MQAR.
2. **Engine III is not necessary for this task.** Full vs No Adaptive Loop: both 100.00% in-domain, both 0.0012 loss; extrapolation 99.45% vs 99.84%. The difference is within single-seed noise. Engine III costs about 3.5 s (2.7%) in this run. It should not be cited as the source of the accuracy.
3. **The Transformer baseline is not tuned.** The 13.12% / 13.05% result is for a small 2-layer model trained for 600 steps with no hyperparameter search. It is not a general attention ceiling.
4. **The comparison is not parameter- or compute-matched.** The Transformer has 543,744 total parameters, including 262,144 positional embedding parameters; without them it has 281,600. TriCore has 348,432 and no positional table. TriCore is also slower in wall-clock time in this Python implementation.
5. **The memory advantage is asymptotic.** At 32K tokens the reported cache ratio is 1,985.9×. At 128 tokens it is only 7.8×. The O(1) advantage matters most at long context.

### 6.4 Grokking-like transition

The Full and No-Adaptive runs both jump from low recall at step 50 to 100.00% at step 100. This is consistent with a grokking-like phase change, but it is a single-seed observation. No claim is made about the transition's stability, sharpness, or dependence on initialization.

## 8. Invariants

Any implementation claiming to be TriCore V3 must preserve:

1. **No attention.** No softmax over sequence positions.
2. **O(1) state.** `h` and `F` shapes are independent of `L`.
3. **Causal shifted write.** Engine II binds `K_{t-1}` to `V_t`; the read uses `Q_t` after the write.
4. **Delta-rule update.** The write is `(V_t - F_{t-1}K_{t-1})K_{t-1}^T`, not a plain Hebbian outer product.
5. **Per-head matrices.** `F` is `[B, H, d_head, d_head]`, not a single shared matrix.
6. **Q/K normalization.** L2 normalization over the head dimension.
7. **Fixed-loop Engine III.** `L_max` is a constant; surprise scales the step size, not the depth.
8. **Independent ablations.** `enable_fast_weight` and `enable_adaptive_loop` gate compute without changing parameter registration.
9. **No positional embedding in TriCore.** Position is carried by the causal convolution and recurrence.
10. **Reproducible artifacts.** `python run_experiment.py` must regenerate the report and plot.

## 9. Non-goals and open work

- No multi-seed mean ± std yet.
- No 32K–128K streaming decode benchmark yet.
- No fused/chunked kernel; the Python per-token loop is the current bottleneck.
- No natural-language pretraining.
- No claim that Engine III helps on harder tasks; that remains untested.
- No claim of parity with a tuned Transformer at scale.

The next specification revision should add multi-seed confidence intervals, a tuned and parameter-matched Transformer, and a real long-context decode benchmark before making broader claims.
