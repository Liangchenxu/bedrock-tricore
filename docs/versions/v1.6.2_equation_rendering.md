# v1.6.2 — PyPI 公式图片化与 HTML 清洗器复盘

## 1. 版本目标

- 解决 PyPI 长描述中 LaTeX/` ```math ` 显示源码的问题。
- 让 GitHub 与 PyPI 对核心公式呈现一致的出版级视觉效果。
- 将 8 组核心架构公式离线渲染为 **300 DPI Computer Modern PNG**，并清理正文行内花括号上下标。
- 保持模型、API、训练协议与所有实测数字不变。

## 2. 核心代码与文件改动

- `results/equations/eq1_addressing.png` … `eq8_state_cache.png`：8 张白底、300 DPI、Computer Modern 公式板。
- `README.md`：Part I / Part II 的核心公式区插入 8 张图，共 **16 个公式图链接**；其余独立公式改为居中 Unicode `<code>`；行内 `F_{t-1}`、`K_{t-1}^{T}`、`v^{(1)}...` 等改为 `Fₜ₋₁`、`Kₜ₋₁ᵀ`、`v⁽¹⁾...`。
- `pyproject.toml`：版本 `1.6.2`。
- 构建脚本使用 `matplotlib.mathtext`，`mathtext.fontset = "cm"`，白底，`bbox_inches="tight"`，`pad_inches=0.12`。

## 3. 真实问题与根因排查

### 3.1 PyPI 的 `nh3` HTML 清洗器禁用 MathJax/KaTeX

PyPI 的 `readme_renderer` 使用 `nh3` 做 HTML sanitization，不含 MathJax/KaTeX 执行环境。` ```math `、`$$...$$` 或裸 LaTeX 不会被渲染成公式，而是作为代码/源码显示。根因是 PyPI 只接受安全的静态 HTML/Markdown，不运行客户端数学库。

### 3.2 非等宽字符导致 ASCII 公式错位

Unicode 上下标、Greek 与中英文混排会破坏等宽假设；同一段 ASCII 框在 GitHub、PyPI 与不同字体下宽度不同，出现边框错位、截断或换行。根因是把“字符数”当成“显示宽度”。

### 3.3 隔离构建访问镜像 403

`python -m build` 的隔离环境会重新安装 `setuptools/wheel`；本机 pip 配置指向清华镜像时返回 403，导致构建中断。根因是构建隔离环境沿用了用户级 index 配置，不是项目依赖缺失。

## 4. 解决方案

- 用 `matplotlib` 离线渲染 8 组核心公式，保存为 PNG；README 只引用仓库内图片，不依赖浏览器数学库。
- 公式图使用统一字体、字号、白底和紧凑裁剪；按图片宽高比设置 `height`，避免小图被拉伸。
- 正文中非图片公式全部改成纯 Unicode；不再保留公式 ` ```text ` 块。
- 构建使用 `python -m build --no-isolation`，或显式指定可用 pip index；发布前用 `twine check` 和 METADATA/PKG-INFO 双重检查。
