## 3. 真实问题与根因排查

### 3.1 GitHub 公式宏 `\operatorname` 不可用

GitHub Markdown 的数学渲染对宏支持有限，`\operatorname{...}` 在部分渲染路径中直接报错或显示为源码。根因是 GitHub 的 MathJax 配置不是完整 TeX 发行版，不能假设任意宏可用。

**修复：** 把 `\operatorname{...}` 统一替换为 `\mathrm{...}`，只使用 GitHub/PyPI 都能稳定处理的基础命令。

### 3.2 PyPI 重复上传同版本返回 403

PyPI 不允许覆盖已上传的版本/文件名。对同一个 `1.6.1` 再次执行 `twine upload` 时，legacy 端点返回：

```text
HTTPError: 403 Forbidden from https://upload.pypi.org/legacy/
```

实际 PyPI JSON 已能看到 wheel 与 sdist，说明第一次上传已成功；第二次是重复请求。根因是发布流程把“重试”当成“幂等操作”，但 PyPI 的版本文件不是幂等的。

### 3.3 PowerShell `Read-Host -AsSecureString` 截断长 Token

在部分 Windows PowerShell/VS Code 终端中，把长 API token 粘贴到 `Read-Host -AsSecureString` 会被截断为单个 `*` 字符，随后 `TWINE_PASSWORD` 实际为空/错误，导致认证失败并返回 403。根因是终端对 SecureString 粘贴路径的处理差异，不是 token 本身失效。

## 4. 解决方案

- 公式：只保留 `\mathrm`、`\frac`、`\sum` 等基础命令；发布前做 ` ```math ` 数量检查。
- 上传：同一版本只上传一次；失败先查 PyPI JSON/Release files，确认是否已经成功，禁止盲目重试。
- Token：改用普通 `Read-Host` 或明确校验长度/前缀的读取方式；确认用户名是 `__token__`；token 必须是 pypi.org 的账号级或 `bedrock-tricore` 项目级 token，而不是 TestPyPI token。
- 发布前：`twine check` + 本地 wheel/sdist 的 METADATA/PKG-INFO 检查 + `pytest -q`。
