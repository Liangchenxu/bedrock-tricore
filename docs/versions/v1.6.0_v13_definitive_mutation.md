# v1.6.0 — V13 Definitive Mutation 与终端故障复盘

## 1. 版本目标

- 将 V12 的“单轮覆写”升级为可区分 Delta 与 Hebbian 的 **V13 状态化热变量实验**。
- 每条序列包含：4 个声明、2 个静态变量、2 个热变量、4 轮循环覆写、6 个对抗 NOP、4 个 alias 查询；共 24 条五 Token 语句、120 Token。
- 在 3 seeds（42/100/2026）、400 steps、batch 64 下比较 Delta Full、Hebbian Full、Fair No-Engine-I 与 2 层 Transformer。
- 证明 Delta 的条件擦除能在不牺牲静态长期保留的情况下，消除多轮覆写产生的陈旧值叠加。

## 2. 核心代码与文件改动

- `tricore/model.py`：保留 V12 的 `enable_delta_rule` 开关；V13 统一使用 `autonomous_syntax=True`、`separator_token=None`、`syntax_tokens=None`、`reset_trace_tokens=None`，并把 `autonomous_entity_max_freq` 从 4 提升到 6（一个热变量出现六次）。
- `tricore/tasks.py`：`generate_stateful_mutation_batch` 生成静态/热变量、四轮 SET、NOP 与 alias 查询；目标只监督 4 个查询位置。
- `run_v13_definitive.py`：四臂、三 seed、可续跑、每 50 步 checkpoint；输出 `results/V13_METRICS.json`、`results/tricore_v13_definitive.png` 与六宫格 `results/tricore_vs_transformer.png`。
- `README.md` / `SPEC_V2.md`：V13 发布段、协议、表格、Welch 检验与适用范围。

## 3. 真实问题与根因排查

### 3.1 V12 单轮覆写让 Hebbian 靠衰减“苟活”

V12 的 Track 7 只做一次旧值→新值覆写。Hebbian 只要衰减足够高，就能在查询时保留新值，导致 Delta 与 Hebbian 的差异被单轮任务掩盖；旧对照的 **p=0.394**，不能拒绝“无差异”假设。

V13 改为同一热键四轮循环覆写。Hebbian 会把四轮外积叠加在同一地址，查询读到旧值和新值的混合；Delta 的 `V_t - F_{t-1}K_{t-1}` 预测误差项在写入前擦除被寻址旧值，因此应显著降低 stale confusion。真正需要的是 **同池、多轮、静态与热变量并存** 的任务，而不是继续调衰减。

### 3.2 Windows VS Code PowerShell 的 `| Out-File` 吞掉完成信号

在 Windows + VS Code PowerShell 中，使用：

```powershell
python run_v13_definitive.py | Out-File run.log
```

会吞掉终端集成依赖的 **OSC 633 完成信号**。Cline 看到的是“命令仍在运行”，于是反复轮询；实际 Python 进程早已结束。根因不是训练脚本卡死，而是管道/重定向改变了终端控制序列，破坏了 shell integration 的完成检测。

## 4. 解决方案

- 任务层：采用四轮同池热覆写，并把静态保留与热覆写放在同一序列，禁止用单一全局衰减同时满足两种需求。
- 模型层：保留 Delta/Hebbian 同预算对照；Delta 只改变擦除项，不改变参数形状、状态大小或优化器预算。
- 终端层：训练脚本改为直接运行，不接 `| Out-File`、`*>` 或任何管道重定向；日志由脚本自行写入，或只在完成后读取文件。
- 结果层：三 seed、400 steps、共享 batch/优化器预算；报告 overall/static/hot 与 hot stale confusion，不只报一个总体均值。
